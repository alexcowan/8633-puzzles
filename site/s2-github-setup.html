Coding with GPT · Session 2 · In class, at your table

Set up for Class 3

Next class you'll lay out one page of your product, and that work should go through version control. Today your team makes a new repo for its project code, gets it onto everyone's machine, and practices the loop you'll use from now on: make a change, stage it, commit it, push it.

When you're done, help someone at your table who isn't. If you get stuck, write down where and why. That note is part of your Class 3 prep.

Done means
  1. Your team has a new repo for its project code (not the practice repo), and everyone on the team can push to it.
  2. The repo's history shows two commits from you: one change Codex made, one you made by hand, each with its own message.
  3. You can see a teammate's files on your own machine.

Install GitHub Desktop and sign in

Download it from desktop.github.com, install it, and sign in with your GitHub account. Desktop handles signing in to GitHub for you, so nothing else on your machine has to.

Show of hands

Create a new repo for your project code

This is a new repo, not the practice repo from your class prep. That one was for learning the steps; this one holds the code you'll build for the rest of the course.

One person per team, on github.com: create the new repository. Short name, no spaces, private, with a README. Then go to Settings → Collaborators and add each teammate by username.

Everyone else: accept the invitation (it's in your email, or at github.com/notifications). Until you do, you can't push.

Pick a spot on your machine

Make a folder for this class somewhere you'll find it again, like Documents/cgpt. Not your Downloads folder, and not inside another repo.

Clone it

In GitHub Desktop: File → Clone repository, pick your team's new project repo (not the practice one), and choose the folder you just made as the local path. You now have two copies Git keeps in step: yours (local) and GitHub's (remote).

Later, when teammates have pushed, Fetch origin and then Pull origin brings their commits down to your copy.

Show of hands

Make a change with Codex

In the Codex app, open the folder Desktop cloned (the repo folder itself, not the class folder above it). Then:

Create a file named notes/YOURNAME-c3.md with one line: the user story for the page I'll lay out for Class 3, which is: [paste your story]. Don't change anything else, and don't commit.

Make a change by hand

In any text editor, create a second file, notes/YOURNAME-questions.md, and write one question you have about Class 3 (or where you got stuck today). Save it. Saving changes the file on your machine and nothing else.

Stage, commit, push in GitHub Desktop

Desktop's Changes list shows both new files. That's everything you've saved but not committed.

Stage one: leave only your c3 file checked. Write a summary that says what it is and why, and click Commit to main.

Then the other: the questions file is still there. Commit it with its own message.

Push: click Push origin. Both commits go to GitHub together. Until you push, nobody else can see them.

Check it on GitHub (web)

Open your team's repo on github.com and click the commit history. Do you see your two commits, with your username and your messages? Click each one: does each show 1 file changed?

Show of hands

Pull your teammates' work

Once your teammates have pushed, in Desktop click Fetch origin, then Pull origin. Their notes files should appear in your folder. If someone's aren't there yet, go help them.
