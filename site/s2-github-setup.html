Set up for Class 3

You have a GitHub account and you've made a change to your team's repo. Next class you'll lay out one page of your product, and that work should go through version control. Today: get your team's repo onto your own machine, open it in Codex, and have Codex commit and push one change for you.

When you're done, help someone at your table who isn't. If you get stuck, write down where and why. That note is part of your Class 3 prep.

Done means
  1. Your Class 3 notes file is on GitHub, in your team's repo, under your username.
  2. The commit changed only that file, and its message says what it is and why.
  3. You can see a teammate's notes file on your own machine.

Check where you are

On GitHub, open your team's repo. Can you see a commit with your username on it? If not, go back to Exhibit 1 of the tech note and finish its checklist first.

Make a folder for this class

Somewhere you'll find it again, like Documents/cgpt. Not your Downloads folder, and not inside another repo.

Open it in Codex

In the Codex app, open that folder. Codex can only read and change files in the folder you give it, so this is where its work will land.

Clone your team's repo

Copy your repo's address from the green Code button on GitHub, then:

Clone https://github.com/OWNER/REPO into this folder. Tell me each step you run and what it does.

Codex will ask before it reaches GitHub. That's the clone using the network; read it and approve. If it fails because git can't sign in to GitHub as you:

Git on this machine can't reach my GitHub account. Help me sign in with the GitHub CLI, one step at a time.

Then open the cloned repo folder itself in Codex, so it's working inside the repo.

Make a start on Class 3

One small file, so you and your teammates never edit the same thing. Put in the user story for the page you'll lay out next class.

Create a file named notes/YOURNAME-c3.md with one line: the user story for the page I'll lay out for Class 3, which is: [paste your story]. Don't change anything else.

Have Codex commit and push it

Stage and commit only that file, with a message that says what it is and why. Show me the commit before you push. Then push it to GitHub.

Codex will ask before the push, because the push reaches GitHub. Read what it's about to run, then approve. Which step is it on: save, stage, commit, or push?

Check it on GitHub

Refresh your team's repo. Is your file there, with your message and your username? Click the commit: does it say 1 file changed? If Codex changed more than you asked, ask it why.
