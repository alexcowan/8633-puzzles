Read the plan before the code

Last time, the HinH parts lookup failed a scenario the story needs: a part number that isn't in the catalog gets a blank screen. We asked an AI to fix it. It drafted a plan and built the app from it. Run the scenarios first. When one fails, find the line in the plan that caused it.

What we're practicing
  1. A Then says what Trent gets. Write it before you run.
  2. When a scenario fails, look in the plan before the code. Five lines are cheaper to read than a hundred.
  3. A plan line is wrong when it contradicts the Then. Fix it in plain words, then rebuild.
