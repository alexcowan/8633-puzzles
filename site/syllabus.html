About the course

AI now does most of the typing in software development. It doesn't decide what's worth building, how to tell whether it works, or what the team should and shouldn't hand to a machine. This course is about those decisions, and about having enough hands-on fluency with code to make them well.

It's for MBAs and other non-engineers, including people with no programming experience. Most students won't spend their careers coding. They'll manage engineers, fund and prioritize development, or lead an organization through rebuilding how it works around AI. The course covers both what teams code and how they code it, since AI is changing both.

The aim is to remove the fear of tinkering with software and to build the habits that make AI-assisted development productive: stating design intent so it can be tested, reading a plan before reading code, choosing between alternatives on their economics, and debugging analytically instead of by trial and error.

How it works

Three parts. Part 1, The Fundamentals, covers the big picture, four repeatable steps for going from design to working software, and the jobs and economics of each layer of an application (UIs, algorithms, data models). Part 2, The Systems, covers stack choices, the product pipeline, observability, and building AI into an application. Part 3, The Pipeline, closes the loop with behavioral observation, A/B tests and evals, and presenting the work.

The four steps. However the tools change, the work of going from design to code comes down to: (1) focusing and communicating design intent, (2) unpacking it into codable steps, (3) effectuating between alternatives, and (4) testing and debugging. They apply across the product pipeline, not just to the application itself.

A running example. The tech notes and puzzles share one example: HVAC in a Hurry (HinH), a fictional regional HVAC service firm building tools for its field technicians.

Tech notes, puzzles, and caselets. Each session has a tech note for reading. Most also have short coding puzzles: a warm-up for class prep and micro puzzles worked in class. Puzzles check themselves by running the code and are assessed by AI against a rubric students can see while they work. Caselets apply the session to the students' own team projects.

Tools. Students use real tools: an AI coding agent (most use Codex, which UVA provides), GitHub for version control, and the browser's developer tools. Teams pick their own development platform early, with one rule: it has to go through version control. Reworking those choices later is part of the learning.
