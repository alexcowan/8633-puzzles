Under a hundred dollars

The story: As Trent the Technician, I want to see only the parts at or under the price the customer gave me, so I can offer a repair they'll say yes to.

Trent, from a job: “Customer said a hundred bucks, tops. I put 100 in the max-price box and got nothing: ‘No parts match.’ So I tried 50 to see if the box worked at all, and it showed me the $184 blower motor.”

The Console is clean: no red. The code runs to the end every time and does the wrong thing. This is the other kind of bug, the kind you find by being analytical: know what should happen, know why you expect the code to do it, and instrument an observation that tells you which assumption is false.

Be ready to explain
  1. For a max price of 100, what Trent should see (the Then) and what he saw.
  2. Which assumption in the code is false, and the one line of observation that showed you.
  3. The change you'd commit: which line or lines, and why there rather than somewhere else.
Opening the developer tools

Use Chrome or another Chromium browser (Edge, Brave, Arc). Press Cmd+Option+J on a Mac (Ctrl+Shift+J on Windows) to open the tools straight to the Console. The Sources panel has this page's files; s4-price/parts-controller.js is the one you're debugging.

To edit that file in the browser and run it again, use Local Overrides; Exhibit 3 of the Session 4 tech note (“Changing Code in the Browser and Running It Again”) walks through it. For this puzzle, the line 20 box below does the same job without overrides.

A useful habit: console.log({price, maxPrice}), with the braces, prints each name next to its value, and the Console shows you what kind of thing each value is. Text prints in quotes; numbers don't.

Safari works too, after you turn on Settings → Advanced → “Show features for web developers.” Ad blockers and password managers sometimes add their own messages to the Console. That's normal; look for the lines that come from this page.
